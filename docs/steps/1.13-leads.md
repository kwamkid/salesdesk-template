### 1. รายการลูกค้า `/leads`
- ช่องค้นหาชื่อหรือเบอร์ + ตัวกรอง: โครงการ · ขั้น · เซลส์ (เฉพาะแอดมิน/ผู้บริหาร) · แคมเปญ · ช่วงวันที่ · "เลยกำหนดตาม" — เก็บค่าใน URL (`?q=&project=&stage=&owner=&campaign=&from=&to=&overdue=1`) หน้า "ทีมขาย" ลิงก์มาที่ `/leads?owner=<id>`
- ดึงข้อมูลด้วย RPC `search_leads` ครั้งเดียว ทีละ 30 แถว มีปุ่ม "โหลดเพิ่ม" (ใช้ `total` ที่ได้มาบอกว่าเหลืออีกกี่ราย)
- แต่ละแถว: ชื่อ · โครงการ · `StageBadge` · วันตามครั้งถัดไป (เลยกำหนดเป็นสีแดงพร้อมคำว่า "เลยกำหนด") · โน้ตล่าสุด · กดแล้วไปหน้าลูกค้า
- จอใหญ่เป็นตาราง มือถือเป็นการ์ดเรียงลงมา · ไม่มีข้อมูล = `EmptyState` พร้อมปุ่มเพิ่มลีด

### 2. เพิ่มลีด `/leads/new`
- บังคับ: ชื่อ · เบอร์โทร · โครงการ (เฉพาะโครงการที่ตัวเองดูแล) — ไม่บังคับ: อีเมล · แคมเปญ (จากตาราง `campaigns` ที่ `is_active` ของโครงการนั้นหรือของทุกโครงการ) · โน้ตแรก
- พิมพ์เบอร์ครบแล้วเรียก RPC `find_phone` ถ้าซ้ำ ให้ขึ้น `Notice` สีเหลือง "เบอร์นี้มีอยู่แล้ว เป็นลูกค้าของ (ชื่อเซลส์) โครงการ (ชื่อ)" ถ้าเป็นของตัวเองมีลิงก์ไปหน้านั้น — เตือนเฉยๆ ไม่ห้ามบันทึก
- บันทึก: insert ลงตาราง `leads` (`owner_id` = ตัวเอง · แอดมินเลือกเซลส์จากสมาชิกของโครงการนั้น: `project_members` + `profiles` ที่ `role = 'sales'` และ `status = 'active'`) ถ้ามีโน้ตแรกให้ตามด้วย RPC `log_activity` ประเภท `other` และวันตามครั้งถัดไป = วันนี้ (ประเภท `other` ไม่นับว่าติดต่อลูกค้าแล้ว ลีดจึงยังอยู่กลุ่ม "ลีดใหม่" ในขั้น 1.14) แล้วเรียก `afterLeadChange()` ไปหน้าลูกค้ารายนั้น
- ตัวกรองเซลส์ในหน้ารายการ ใช้ `profiles` ที่ `role = 'sales'`

### 3. หน้าลูกค้า `/leads/[id]`
บนสุด: ชื่อ · `StageBadge` · โครงการ · เซลส์เจ้าของ · ปุ่ม **โทร** (`tel:` ใช้ `telHref`) · วันตามครั้งถัดไป · เวลานัดชม (ถ้ามี)

ปุ่มหลัก 3 ปุ่ม (เซลส์เจ้าของและแอดมินเท่านั้น ผู้บริหารไม่เห็น):
1. **บันทึกกิจกรรม** — เปิด `Sheet` ช่อง: ประเภท (`ACTIVITY_TYPES`) · โน้ต · วันตามครั้งถัดไป (บังคับเฉพาะลีดที่ยังไม่ปิด) → RPC `log_activity` → ปิดหน้าต่างทันที
   - ปุ่มลัด **พรุ่งนี้ / 3 วัน / 7 วัน** อยู่นอก `Field` (`Field` เป็น `<label>` ปุ่มข้างในจะถูกกดเอง) และ**กดแล้วบันทึกเลย**ถ้าพิมพ์โน้ตแล้ว (บันทึกผลจบใน 3 ครั้งกด) · มีช่องเลือกวันเองสำหรับวันอื่น
   - ทำเป็น component ใช้ซ้ำได้ที่ `src/components/lead/log-activity-sheet.tsx` + Server Action ที่ `src/components/lead/log-activity-action.ts` (ขั้น 1.14 ใช้ต่อ ไม่ต้องเขียนใหม่)
2. **เปลี่ยนขั้น** — เลือกขั้นจาก `STAGES` → RPC `change_stage` · เลือก "ไม่ซื้อ" ต้องเลือกเหตุผล (`lost_reasons` ที่ `is_active`) · "นัดชมโครงการ" ต้องใส่วันเวลานัด (`datetime-local` เป็นเวลาไทย ต่อท้าย `+07:00` ก่อนส่งเป็น `p_appointment_at`) · ขั้นที่ยังไม่ปิดต้องมีวันตามครั้งถัดไป · ขั้น จอง/ทำสัญญา/โอน ใช้ `ConfirmCard`
3. **เช็กอินพาชม** — วาง `<VisitCheckIn leadId={...} nextFollowUp={...} />` ที่ทำไว้แล้ว (ถ่ายรูป ย่อรูป อัปโหลดเบื้องหลังให้เอง)

ใครแก้ได้ (`editable`): เซลส์เจ้าของลีด หรือแอดมิน — `me.role === "admin" || lead.owner_id === me.id`

ส่วนที่ทำไว้แล้ว ให้วางลงในหน้าตามลำดับนี้:
- `<LeadUnits leadId projectId editable />` — แปลงที่สนใจ / แปลงที่จอง (`src/components/lead/lead-units.tsx`)
- `<DocumentsButton leadId stage />` — ปุ่มออกเอกสารตามขั้น (`src/components/lead/documents-button.tsx`)
- `<LoanScreeningCard leadId editable />` — ผลคัดกรองสินเชื่อ (`src/components/lead/loan-screening-card.tsx`)

ข้อมูลลูกค้า (แก้ได้โดยเจ้าของและแอดมิน): ชื่อ · เบอร์ · อีเมล · แคมเปญ · ที่อยู่ · เลขบัตรประชาชน (ใช้ออกเอกสาร) — update ตาราง `leads` ตรง ๆ (RLS กันสิทธิ์ให้แล้ว)

ไทม์ไลน์: กิจกรรมทั้งหมดเรียงจากล่าสุด (ตาราง `activities` + ชื่อผู้บันทึก `author:profiles!created_by(full_name)` — ต้องใส่ `!created_by` เพราะมีหลายลิงก์ไป profiles) รวมกับประวัติเปลี่ยนขั้น (`stage_history` + `profiles!changed_by`) · กิจกรรมที่มีรูปแสดง `<ActivityPhoto path={...} />` · กิจกรรมที่รูปยังอัปโหลดไม่เสร็จแสดง `<PhotoUploading activityId={...} />` (อยู่ใน `visit-check-in.tsx`)

## ใช้ของที่มีแล้ว (ห้ามสร้างซ้ำ)

- ฐานข้อมูล: `supabase/migrations/0003_leads.sql` — RPC `search_leads` `find_phone` `log_activity` `change_stage` · กติกาบังคับอยู่ในฐานข้อมูลแล้ว แปลง error เป็นไทยในไฟล์เดียว `src/components/lead/rpc-error.ts`:
  `not allowed` → ไม่มีสิทธิ์แก้ลูกค้ารายนี้ · `note required` → ต้องพิมพ์โน้ต · `next follow-up required` → ต้องใส่วันตามครั้งถัดไป · `next follow-up in the past` → วันตามต้องไม่ใช่วันที่ผ่านมาแล้ว · `lost reason required` → ต้องเลือกเหตุผลที่ไม่ซื้อ · `appointment time required` → ต้องใส่วันเวลานัดชม
- ชิ้นส่วนกลางอยู่ใน 3 ไฟล์: `button.tsx` (Button) · `field.tsx` (Field Input Select Textarea) · `card.tsx` (Card Badge StageBadge EmptyState Loading Notice PageTitle) · `confirm-card.tsx` (Sheet ConfirmCard)
- หลังทุก Server Action ที่ เพิ่มลีด / บันทึกกิจกรรม / เปลี่ยนขั้น ให้เรียก `afterLeadChange()` จาก `@/lib/background` (ส่ง event ไป Meta และแจ้งเตือนให้เอง)
- `src/components/ui/*` · `src/config/stages.ts` · `src/config/activities.ts` · `src/lib/format.ts` · `requireMe()` จาก `src/lib/auth.ts`

## ตรวจผลยังไง (ผู้เรียนทำเอง)

1. `npm run dev` แล้วเปิด http://localhost:3000/leads/new — เพิ่มลีด 1 ราย (เบอร์ของตัวเอง)
2. เพิ่มอีกรายด้วยเบอร์เดิม → ต้องขึ้นเตือนว่าเบอร์ซ้ำ
3. เปิดหน้าลูกค้า → กด **บันทึกกิจกรรม** ลองไม่ใส่วันตามครั้งถัดไป → ต้องบันทึกไม่ได้
4. เปลี่ยนขั้นเป็น "ไม่ซื้อ" → ต้องบังคับเลือกเหตุผล
5. กดปุ่ม **โทร** บนมือถือ → ต้องเปิดแอปโทรศัพท์
6. ย่อจอเหลือ 375px (หรือรัน `/ui-check` ตรวจทุกขนาดจอ) → ไม่มีอะไรล้นจอ
7. `npm run build` ผ่าน แล้ว commit ชื่อ `Step 1.13: leads, add lead, customer page`
