# SalesDesk — สเปกระบบต้นแบบ

ร่าง v0.2 · 21 พ.ย. 2026 · สำหรับคอร์ส AI 2 วัน ผู้ประกอบการบ้านจัดสรร

เปลี่ยนจาก v0.1: ปรับเป็น 3 ระดับผู้ใช้ (แอดมิน ผู้บริหาร เซลส์) เพิ่มการเชิญผู้ใช้ และไฟล์รายชื่อสำหรับ Meta มีแค่เบอร์กับอีเมล

สถานะ: ร่างจากที่คุยกัน ยังไม่ได้สร้างจริง ตัวเลขมูลค่าในเอกสารเป็นตัวอย่างเท่านั้น

---

## 1. ระบบนี้ทำอะไร

ระบบติดตามลูกค้าและงานขายของบริษัทบ้านจัดสรร ใช้ได้หลายโครงการในบริษัทเดียว

ผู้ใช้ได้อะไร

- **เซลส์** เปิดมาเห็นทันทีว่าวันนี้ต้องโทรหรือตามใคร ไม่ต้องจำเอง
- **ผู้บริหาร** เห็นว่าลูกค้าแต่ละรายอยู่ขั้นไหน เป็นของเซลส์คนไหน ถูกตามกี่ครั้ง และเสียลูกค้าเพราะอะไร
- **ฝ่ายการตลาด** รู้ว่าแคมเปญไหนได้ลูกค้าที่มาชมและจองจริง และส่งข้อมูลกลับไป Meta ได้

เครื่องมือ: Next.js บน Vercel (ฟรี) · Supabase (ฟรี) · cron-job.org (ฟรี) · ไม่ใช้ Claude API

## 2. ผู้ใช้และสิทธิ์

มี 3 ระดับ แต่ละระดับเปิดแอปแล้วเจอหน้าแรกไม่เหมือนกัน (รายละเอียดเมนูอยู่ในไฟล์ docs/DESIGN.md)

| ระดับ | หน้าแรก | เห็นอะไร | ทำอะไรได้ |
|---|---|---|---|
| แอดมิน | งานรอดำเนินการ | ทุกโครงการ ทุกผู้ใช้ | เชิญและอนุมัติผู้ใช้ กำหนดระดับ สร้างโครงการ ตั้งค่าระบบ ย้ายลีด Export |
| ผู้บริหาร | ภาพรวมยอดขาย | ทุกโครงการ หรือเฉพาะโครงการที่ได้รับมอบหมาย | ดูรายงาน ดูลูกค้าทุกราย Export แก้การตั้งค่าไม่ได้ |
| เซลส์ | งานของฉันวันนี้ | เฉพาะลีดของตัวเอง | เพิ่มลีด บันทึกกิจกรรม เปลี่ยนขั้น เช็กอินพาชม |

การเชิญและการอนุมัติ

1. แอดมินกด "เชิญผู้ใช้" เลือกระดับและโครงการ ระบบสร้างลิงก์เชิญให้ก๊อปไปส่งทาง LINE ลิงก์ใช้ได้ครั้งเดียวและมีวันหมดอายุ
2. คนที่สมัครผ่านลิงก์เชิญเข้าใช้ได้ทันทีตามระดับที่แอดมินตั้งไว้
3. คนที่สมัครเองโดยไม่มีลิงก์จะอยู่สถานะ "รออนุมัติ" และไปขึ้นในหน้าแรกของแอดมิน
4. พนักงานลาออก แอดมินปิดสิทธิ์ได้ และย้ายลีดทั้งหมดไปให้คนอื่นได้ในครั้งเดียว

การล็อกอิน

ล็อกอินด้วยบัญชี Google อย่างเดียว (ไม่มีรหัสผ่าน) วิธีตั้งค่าอยู่ใน docs/guides/google-login.md

สิทธิ์ทั้งหมดบังคับที่ฐานข้อมูลด้วย Row Level Security ของ Supabase ไม่ใช่แค่ซ่อนเมนู

## 3. ข้อมูลที่ระบบเก็บ

| ชุดข้อมูล | เก็บอะไร |
|---|---|
| บริษัท (ตั้งค่า) | ชื่อบริษัท, Pixel ID, token ของ Conversions API (ชุดเดียวทั้งบริษัท) |
| โครงการ | ชื่อ, ทำเล, เพจที่ใช้ยิงแอด, สถานะเปิด/ปิดการขาย, มูลค่าต่อขั้นของโครงการนี้ |
| ผู้ใช้ | ชื่อ, อีเมล, ระดับ, สถานะอนุมัติ, โครงการที่ดูแล (ได้หลายโครงการ) |
| ลีด (ลูกค้า) | ชื่อ, เบอร์โทร (บังคับ), อีเมล (ไม่บังคับ), โครงการ, เซลส์เจ้าของ, แคมเปญที่มา, ขั้นปัจจุบัน, วันตามครั้งถัดไป |
| กิจกรรม | ลีด, ประเภท (โทร / แชต / นัด / พาชม / อื่นๆ), โน้ต, รูปแนบ, วันเวลา, ผู้บันทึก |
| ประวัติการเปลี่ยนขั้น | ลีด, จากขั้นไหนไปขั้นไหน, เมื่อไร, โดยใคร |
| เหตุผลที่ไม่ซื้อ | รายการให้เลือก แก้ไขได้ในหน้าตั้งค่า |
| บันทึกการส่ง Meta | event ที่ส่ง, เวลา, สำเร็จหรือไม่, ข้อความ error |

## 4. ขั้นของลูกค้า และ event ที่ส่งไป Meta

| ขั้น | ความหมาย | ส่ง event ไป Meta | มูลค่า (ตัวอย่าง) |
|---|---|---|---|
| 1. ลีดใหม่ | เพิ่งได้เบอร์ ยังไม่ได้คุย | ส่ง | ไม่ใส่ |
| 2. ลีดคุณภาพ | คุยแล้ว สนใจจริง งบถึง | ส่ง | ตั้งเองรายโครงการ |
| 3. นัดชมโครงการ | มีวันนัดแล้ว | ส่ง | ตั้งเองรายโครงการ |
| 4. มาชมแล้ว | เช็กอินพร้อมรูปที่หน้างาน | ส่ง | ตั้งเองรายโครงการ |
| 5. จอง | วางเงินจอง | ส่ง | ตั้งเองรายโครงการ |
| 6. ทำสัญญา | เซ็นสัญญาจะซื้อจะขาย | ส่ง | ตั้งเองรายโครงการ |
| 7. โอน | โอนกรรมสิทธิ์ | ส่ง | ราคาบ้าน |
| ไม่ซื้อ | ต้องเลือกเหตุผล | ไม่ส่ง | - |
| ไม่มีคุณภาพ | เบอร์ผิด ไม่สนใจ งบไม่ถึง | ไม่ส่ง (ใช้ทำ audience กันออก) | - |

หมายเหตุ

- แอดมินเปิดปิดการส่งและแก้มูลค่าของแต่ละขั้นได้ในหน้าตั้งค่า แยกรายโครงการ
- Meta นับผลให้แอดภายในช่วงเวลาจำกัดหลังคลิก ขั้นที่ 2 ถึง 4 จึงสำคัญกับโฆษณามากกว่าขั้น 6 ถึง 7 ซึ่งมักมาช้าเกิน
- ชื่อ event ที่จะใช้กับแต่ละขั้นยังไม่ได้กำหนด ต้องเลือกตอนสร้างจริง
- ระบบส่งเบอร์โทรและอีเมลแบบเข้ารหัส โดยแปลงเบอร์เป็นรูปแบบสากล (66...) ก่อน

## 5. หน้าจอ

### 5.1 หน้าแรกของเซลส์: "งานของฉันวันนี้"

เปิดระบบแล้วเจอหน้านี้ก่อน แบ่งเป็น 4 กลุ่ม เรียงตามความเร่งด่วน

1. **เลยกำหนดแล้ว** (สีแดง) พร้อมจำนวนวันที่เลย
2. **ต้องตามวันนี้**
3. **ลีดใหม่ที่ยังไม่ได้ติดต่อ**
4. **7 วันข้างหน้า**

แต่ละรายการแสดง ชื่อ, โครงการ, ขั้นปัจจุบัน, โน้ตครั้งล่าสุด และมีปุ่มโทร (กดแล้วโทรออกจากมือถือ) กับปุ่มบันทึกผล

### 5.2 เพิ่มลีด

ช่องบังคับ: ชื่อ, เบอร์โทร, โครงการ
ช่องไม่บังคับ: อีเมล, แคมเปญที่มา (เลือกจากรายการ), โน้ตแรก
ระบบเตือนถ้าเบอร์ซ้ำกับลีดที่มีอยู่ และบอกว่าเป็นของเซลส์คนไหน

### 5.3 หน้าลูกค้า

- ข้อมูลลูกค้า ขั้นปัจจุบัน เซลส์เจ้าของ
- ไทม์ไลน์กิจกรรมทั้งหมด เรียงจากล่าสุด
- ปุ่ม **บันทึกกิจกรรม** บังคับ 3 ช่อง: ประเภท, โน้ต, วันตามครั้งถัดไป
- ปุ่ม **เปลี่ยนขั้น** ถ้าเลือก "ไม่ซื้อ" ต้องเลือกเหตุผล
- ปุ่ม **เช็กอินพาชม** ถ่ายรูปคู่กับลูกค้า ระบบบันทึกเวลา ย่อรูปก่อนเก็บ แล้วเลื่อนขั้นเป็น "มาชมแล้ว"

กติกา follow-up: ลีดที่ยังไม่ปิด (ยังไม่โอน ไม่ใช่ "ไม่ซื้อ" และไม่ใช่ "ไม่มีคุณภาพ") ต้องมีวันตามครั้งถัดไปเสมอ บันทึกไม่ได้ถ้าเว้นว่าง

### 5.4 รายการลูกค้า

ค้นหาด้วยชื่อหรือเบอร์ กรองตาม โครงการ, ขั้น, เซลส์, แคมเปญ, ช่วงวันที่ และ "เลยกำหนดตาม"

### 5.5 Dashboard ผู้บริหาร

- Funnel: จำนวนลีดในแต่ละขั้น และอัตราเปลี่ยนจากขั้นหนึ่งไปขั้นถัดไป
- รายเซลส์: ลีดที่ถือ, กิจกรรมต่อสัปดาห์, งานตามที่เลยกำหนด, นัดชม, จอง
- รายโครงการ: ลีด, นัดชม, จอง, โอน, มูลค่ารวม
- รายแคมเปญ: ลีด, ลีดคุณภาพ, มาชม, จอง
- เหตุผลที่ไม่ซื้อ เรียงจากมากไปน้อย
- กรองได้ตามโครงการและช่วงวันที่

### 5.6 Export

ออกเป็น CSV ที่เปิดใน Excel แล้วอ่านภาษาไทยได้ กรองตาม โครงการ, เซลส์, ขั้น, ช่วงวันที่ ก่อนออกไฟล์

| ไฟล์ | เนื้อหา | ใช้ทำอะไร |
|---|---|---|
| ลูกค้าทั้งหมด | 1 แถวต่อลูกค้า: ชื่อ, เบอร์, โครงการ, เซลส์, แคมเปญ, ขั้น, มาชมหรือยัง, วันที่มาชม, วันตามครั้งถัดไป, โน้ตล่าสุด | ประชุมทีม ส่งผู้บริหาร |
| กิจกรรมทั้งหมด | 1 แถวต่อกิจกรรม: ลูกค้า, ประเภท, โน้ต, วันเวลา, เซลส์ | ตรวจการทำงานย้อนหลัง |
| งานตามที่ค้าง | ลูกค้าที่ถึงหรือเลยกำหนดตาม แยกรายเซลส์ | ผู้บริหารไล่งาน |
| รายชื่อสำหรับ Meta | มีแค่ 2 คอลัมน์ คือเบอร์และอีเมล ไม่มีข้อมูลอื่น ผู้ใช้เลือกกลุ่ม (เช่น ไม่มีคุณภาพ หรือ จองแล้ว) แล้วกดปุ่มเดียว ได้ไฟล์ที่พร้อมใช้ ไม่ต้องลบคอลัมน์เอง | ส่งให้ Claude + Meta MCP สร้าง custom audience |
| สรุปสำหรับ Claude | ตัวเลข funnel และรายแคมเปญเป็นข้อความ | ก๊อปไปให้ Claude วิเคราะห์คู่กับข้อมูลโฆษณา |

**ชุดวิเคราะห์ทีมขายสำหรับ Claude** (หน้าสำคัญของผู้บริหาร)

ปุ่มเดียวออกไฟล์ที่พร้อมส่งให้ Claude วิเคราะห์การทำงานของเซลส์ ประกอบด้วย

- กิจกรรมทั้งหมดในช่วงที่เลือก พร้อมโน้ตของเซลส์
- สรุปรายเซลส์: จำนวนลีดที่ถือ, กิจกรรมต่อสัปดาห์, เวลาเฉลี่ยจากได้ลีดถึงติดต่อครั้งแรก, งานที่เลยกำหนด, อัตราเปลี่ยนเป็นนัดชมและจอง, เหตุผลที่เสียลูกค้า
- ไม่มีเบอร์โทรและอีเมลของลูกค้าในไฟล์นี้ ชื่อลูกค้าแสดงเป็นรหัส
- หน้าเดียวกันมีคำสั่งตัวอย่างให้ก๊อปไปวางใน Claude คู่กับไฟล์

ข้อควรบอกผู้ใช้: ตัวเลขบอกปริมาณงานและผลลัพธ์ แต่เซลส์ที่ถือโครงการขายยากหรือได้ลีดคุณภาพต่ำจะดูแย่กว่าความจริง ผลวิเคราะห์จึงใช้ประกอบการคุยกับทีม ไม่ใช้ตัดสินแทน

สิทธิ์ Export: แอดมินและผู้บริหาร เซลส์ออกได้เฉพาะรายการของตัวเอง และออกไฟล์รายชื่อสำหรับ Meta ไม่ได้

### 5.7 ตั้งค่า (แอดมิน)

- โครงการ: เพิ่ม แก้ไข ปิดการขาย
- ผู้ใช้: อนุมัติ กำหนดระดับ มอบหมายโครงการ ปิดสิทธิ์ ย้ายลีด
- ขั้นและมูลค่า: แก้มูลค่าและเปิดปิดการส่ง event รายโครงการ
- Meta: ช่องวาง Pixel ID และ token พร้อมปุ่ม "ทดสอบส่ง"
- รายการแคมเปญ และรายการเหตุผลที่ไม่ซื้อ

## 5.8 ผังโครงการ (module เสริม)

แสดงรูปผังจริงของโครงการเป็นพื้น มีหมุดของแต่ละแปลงทับอยู่ กดได้

ข้อมูลของแปลง: เลขแปลง, โซนหรือเฟส, ขนาด, แบบบ้าน, ราคา, สถานะ, ตำแหน่งบนรูป (เก็บเป็นสัดส่วนของรูป)

สถานะแปลง: ว่าง · มีคนสนใจ · จอง · ทำสัญญา · โอน (สีต่างกัน และมีตัวอักษรกำกับ)

การใช้งาน

- ซูมและเลื่อนผังด้วยนิ้ว หมุดคงขนาดที่กดง่ายทุกระดับซูม
- ค้นหาเลขแปลง แล้วผังเลื่อนไปที่แปลงนั้นพร้อมไฮไลต์
- โครงการใหญ่แบ่งเป็นหลายรูปตามโซนหรือเฟส สลับด้วยแถบด้านบน
- แตะหมุดแล้วขึ้นแผ่นข้อมูลด้านล่าง มีปุ่มยืนยันก่อนบันทึกทุกครั้ง
- **เลือกแปลงได้ 2 ทางเสมอ:** (1) แตะบนผัง (2) เลือกจาก dropdown ที่พิมพ์ค้นหาเลขแปลงได้ ทั้งสองทางอยู่ในหน้าเดียวกันและบันทึกลงข้อมูลชุดเดียวกัน ถ้าผังโหลดไม่ขึ้น กดไม่ติด หรือโครงการยังไม่ได้อัปโหลดผัง ทาง dropdown ยังใช้งานได้ครบ
- โครงการที่ยังไม่มีรูปผังหรือยังไม่ได้ปักหมุด ระบบแสดงเฉพาะ dropdown และรายการแปลง ไม่ขึ้นหน้าว่าง
- กรองดูเฉพาะแปลงว่างได้ทั้งในผังและในรายการ
- จากหน้าลูกค้า เซลส์กด "เลือกแปลงที่สนใจ" แล้วแตะบนผัง ลูกค้าหนึ่งรายสนใจได้หลายแปลง
- หมุดแสดงจำนวนคนที่สนใจแปลงนั้น
- การจองล็อกที่ฐานข้อมูล แปลงเดียวจองซ้อนไม่ได้
- เมื่อลูกค้าผูกกับแปลงแล้ว มูลค่าที่ส่งไป Meta ตอนจองและโอนใช้ราคาของแปลงนั้น

สถานะแปลงแบบเรียลไทม์

- เมื่อมีคนเปลี่ยนสถานะแปลง ทุกเครื่องที่เปิดหน้าผังหรือรายการแปลงอยู่จะเห็นสีเปลี่ยนเองโดยไม่ต้องรีเฟรช (ใช้ Supabase Realtime)
- ถ้าการเชื่อมต่อเรียลไทม์หลุด ระบบโหลดข้อมูลใหม่ทุกครั้งที่เปิดหน้า และมีการดึงลงเพื่อรีเฟรช พร้อมบอกเวลาที่อัปเดตล่าสุด
- แถบสรุปด้านบนของหน้า: ว่าง กี่แปลง · มีคนสนใจ · จอง · ทำสัญญา · โอน และมูลค่ารวมของแปลงที่ยังว่าง
- เซลส์ทุกคนเห็นสถานะแปลงของโครงการที่ตัวเองดูแล แต่เห็นชื่อลูกค้าเฉพาะแปลงของลูกค้าตัวเอง แปลงของคนอื่นเห็นแค่สถานะและชื่อเซลส์ที่ถือ
- ผู้บริหารและแอดมินเห็นทุกแปลงพร้อมชื่อลูกค้าและเซลส์
- ทุกการเปลี่ยนสถานะเก็บประวัติว่าใครเปลี่ยน เมื่อไร
- เปลี่ยนเป็น "จอง" ได้โดยเซลส์ แต่การยกเลิกจองและการแก้กลับเป็น "ว่าง" ทำได้เฉพาะแอดมิน

การปักหมุด มี 2 ทาง ใช้ร่วมกัน

1. **ปักอัตโนมัติด้วย Claude Code** (ทำบนคอมของแอดมิน ไม่ได้ทำในแอป)
   - วางรูปผังความละเอียดสูงที่มีเลขแปลงพิมพ์อยู่ (เช่น A01, A02) ในโฟลเดอร์โปรเจกต์
   - สั่ง Claude Code ให้อ่านเลขแปลงและหาตำแหน่งจากรูป โดยใช้โปรแกรมอ่านตัวอักษรจากภาพ (OCR) ที่ติดตั้งในเครื่อง
   - ได้ไฟล์ตำแหน่ง (เลขแปลง + พิกัด) พร้อมรายงานว่าเจอกี่แปลง และแปลงไหนหาไม่เจอ
   - นำเข้าไฟล์ผ่านปุ่ม "นำเข้าตำแหน่งแปลง" ในหน้าจัดการโครงการ
2. **โหมดแก้หมุดในแอป** แอดมินตรวจผลบนผัง ลากหมุดที่คลาดเคลื่อน และแตะเพิ่มแปลงที่หาไม่เจอ

ข้อจำกัด: ความแม่นของการปักอัตโนมัติขึ้นกับความคมชัดของรูปและขนาดตัวเลข เลขที่เล็ก เอียง หรือเขียนด้วยมืออาจอ่านไม่ออก จึงต้องมีขั้นตรวจในแอปเสมอ วิธีนี้ยังไม่ได้ทดสอบกับผังจริง

## 5.9 ออกเอกสารจากระบบ

เซลส์กดปุ่ม "ออกเอกสาร" ในหน้าลูกค้า ระบบเติมข้อมูลลงในต้นแบบของบริษัท แล้วเปิดหน้าพร้อมพิมพ์ ไม่ผ่าน Claude และไม่ส่งข้อมูลออกนอกระบบ

หลักการ

- **ถ้อยคำในเอกสารคงเดิมทุกตัวอักษร** ระบบเติมเฉพาะช่องที่กำหนด เช่น ชื่อ ที่อยู่ เลขบัตรประชาชน เบอร์โทร โครงการ เลขแปลง ขนาด ราคา เงินจอง วันที่ ชื่อเซลส์
- **ผูกเอกสารกับขั้นของลูกค้า** แต่ละขั้นมีเอกสารที่ออกได้ เช่น ขั้นจองออกใบจอง ขั้นทำสัญญาออกสัญญาจะซื้อจะขาย แอดมินกำหนดได้ว่าขั้นไหนใช้เอกสารอะไร
- **ต้นแบบเป็นของแต่ละบริษัท** ผู้เรียนส่งไฟล์ต้นแบบของตัวเอง แล้วให้ Claude Code แปลงเป็นหน้าพิมพ์ในแอป (ทำบนเครื่องของคนทำระบบ ครั้งเดียวต่อเอกสาร)
- **ก่อนพิมพ์มีหน้าตรวจ** แสดงเอกสารที่เติมแล้ว ช่องที่ยังว่างขึ้นสีเตือน เซลส์แก้ข้อมูลได้ก่อนกดพิมพ์
- **พิมพ์หรือบันทึกเป็น PDF** จากปุ่มเดียว จัดหน้าตามขนาดกระดาษที่กำหนด ขนาดกระดาษและรูปแบบการจัดหน้ายังไม่ได้ตกลง
- **เก็บประวัติ** ว่าออกเอกสารอะไร ให้ลูกค้ารายไหน เมื่อไร โดยใคร

ข้อมูลที่ต้องเก็บเพิ่มในระบบ: ที่อยู่ลูกค้า และเลขบัตรประชาชน

- เลขบัตรประชาชนเห็นได้เฉพาะเซลส์เจ้าของลีด ผู้บริหาร และแอดมิน หน้ารายการแสดงแบบปิดบางหลัก
- เลขบัตรไม่อยู่ในไฟล์ Export ใดๆ และไม่ถูกส่งไป Meta

ข้อจำกัด

- เอกสารที่จัดหน้าซับซ้อน (ตารางหลายชั้น หลายหน้า มีลายน้ำ) อาจต้องให้ Claude Code ปรับหลายรอบกว่าจะตรงต้นฉบับ
- เมื่อบริษัทแก้ถ้อยคำในสัญญา ต้องแก้ต้นแบบในระบบด้วย ควรมีผู้รับผิดชอบ
- ต้นแบบสัญญาควรผ่านการตรวจของที่ปรึกษากฎหมายของบริษัทก่อนนำมาใช้ ระบบไม่ได้ตรวจเนื้อหาทางกฎหมาย

## 6. การแจ้งเตือน

- ในระบบ: ตัวเลขงานค้างบนหน้าแรก และแถบสีแดงสำหรับงานที่เลยกำหนด
- งานประจำวัน: cron-job.org เรียกระบบทุกเช้าเพื่อคำนวณงานค้างและส่ง event ที่ส่งไม่สำเร็จซ้ำ
- Push บนมือถือ: สรุปงานตามทุกเช้าสำหรับเซลส์ สรุปยอดทุกเย็นสำหรับผู้บริหาร และแจ้งทันทีเมื่อมีลีดใหม่ การจอง หรือผู้ใช้รออนุมัติ รายละเอียดอยู่ในไฟล์ docs/DESIGN.md หัวข้อ 4.1
- การส่งสรุปทางอีเมลหรือ LINE ยังไม่อยู่ในต้นแบบ เป็นหัวข้อต่อยอด

## 7. ขอบเขต

**สร้างในคลาส**

- ล็อกอิน 3 ระดับผู้ใช้ การเชิญ และการอนุมัติ
- ติดตั้งเป็นแอปบนมือถือ (PWA) และแจ้งเตือน push
- แปลง สถานะเรียลไทม์ และผังโครงการ
- ออกเอกสารจากต้นแบบของบริษัท
- หลายโครงการ
- เพิ่มลีด หน้าลูกค้า บันทึกกิจกรรม วันตามครั้งถัดไป
- หน้า "งานของฉันวันนี้"
- เช็กอินพาชมพร้อมรูป
- ขั้นของลูกค้า และเหตุผลที่ไม่ซื้อ
- ส่ง event ไป Meta ด้วยเบอร์โทรและอีเมล
- Dashboard และ Export
- ผลคัดกรองสินเชื่อต่อลูกค้า: สถานะ (ยังไม่คัดกรอง · รอเอกสาร · ยื่นแล้ว · ผ่าน · ไม่ผ่าน) · อาชีพ · รายได้ต่อเดือน · ภาระหนี้ต่อเดือน · วงเงินที่ต้องการ · ธนาคารที่ยื่น · วงเงินที่อนุมัติ · เหตุผลที่ไม่ผ่าน · ใครบันทึก เมื่อไร (ข้อมูลชุดนี้ใช้ต่อในหัวข้อคัดกรองสินเชื่อ 2.14)

**แบบฝึกหัดให้ผู้เรียนเพิ่มเอง**

- ข้อมูลคัดกรองลูกค้า (งบ แบบบ้าน ผู้ตัดสินใจ ช่วงเวลาที่จะซื้อ)
- เงินจอง วันทำสัญญา

**ไม่อยู่ในต้นแบบ**

- ดึงข้อความแชตจาก Messenger หรือ LINE
- ส่ง event แบบแชตด้วย PSID
- สร้าง audience อัตโนมัติจากในระบบ (ใช้ Export + Meta MCP แทน)
- ล็อกอินด้วย LINE
