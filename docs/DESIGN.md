# SalesDesk — เมนู ธีม และกติกาทางเทคนิค

ร่าง v0.1 · 21 พ.ย. 2026 · ต้นฉบับอยู่ในไฟล์ Handoff ของคอร์ส ภาค 3

เอกสารนี้ตั้งใจให้วางไว้ในโฟลเดอร์โปรเจกต์ เพื่อให้ Claude Code อ่านก่อนสร้างทุกหน้า

---

## 1. หลักการออกแบบ

1. **มือถือก่อน** เซลส์ใช้มือถือที่หน้างาน ทุกหน้าต้องใช้นิ้วเดียวได้
2. **หนึ่งหน้าจอ หนึ่งงาน** ไม่ทำหน้ายาว เนื้อหาหลักต้องจบในจอเดียว
3. **กดน้อยที่สุด** งานที่ทำบ่อย (บันทึกผลการโทร) ต้องจบใน 3 ครั้งกด
4. **ผู้ใช้ไม่ต้องทำอะไรต่อเอง** ไฟล์ที่ระบบออกให้ต้องพร้อมใช้ทันที

## 2. เมนูแยกตามระดับผู้ใช้

มือถือใช้แถบเมนูล่าง (สูงสุด 5 ปุ่ม) จอใหญ่ใช้เมนูซ้าย รายการเมนูชุดเดียวกัน

### 2.1 เซลส์

หน้าแรก: **วันนี้**

| ปุ่ม | หน้า | เนื้อหา |
|---|---|---|
| วันนี้ | งานของฉันวันนี้ | เลยกำหนด · ต้องตามวันนี้ · ลีดใหม่ · 7 วันข้างหน้า |
| ลูกค้า | ลูกค้าของฉัน | ค้นหา กรองตามขั้นและโครงการ |
| ＋ (ปุ่มกลาง) | เพิ่มลีด | ชื่อ เบอร์ โครงการ |
| แปลง | ผังและสถานะแปลง | ผังโครงการแบบเรียลไทม์ สลับเป็นรายการได้ กรองเฉพาะแปลงว่าง |
| ฉัน | โปรไฟล์และผลงาน | ผลงานเดือนนี้เทียบเดือนก่อน โครงการที่ดูแล ตั้งค่าแจ้งเตือน ติดตั้งแอป ออกจากระบบ |

### 2.2 ผู้บริหาร

หน้าแรก: **ภาพรวม**

| ปุ่ม | หน้า | เนื้อหา |
|---|---|---|
| ภาพรวม | ภาพรวมยอดขาย | ตัวเลขหลัก 4 ตัว (ลีดใหม่ นัดชม จอง โอน) · funnel · งานตามที่เลยกำหนดทั้งทีม |
| โครงการ | รายโครงการ | เทียบโครงการ กดเข้าไปดู funnel แคมเปญ และผังสถานะแปลงแบบเรียลไทม์ของโครงการนั้น พร้อมจำนวนแปลงว่างและมูลค่าคงเหลือ |
| ทีมขาย | รายเซลส์ | กิจกรรมต่อสัปดาห์ งานค้าง นัดชม จอง กดเข้าไปดูลูกค้าของเซลส์คนนั้น |
| ลูกค้า | ลูกค้าทั้งหมด | ค้นหา กรอง ดูไทม์ไลน์ (อ่านอย่างเดียว) |
| รายงาน | Export | ไฟล์ 5 แบบ และข้อความสรุปสำหรับ Claude |

### 2.3 แอดมิน

หน้าแรก: **งานรอดำเนินการ**

| ปุ่ม | หน้า | เนื้อหา |
|---|---|---|
| งานรอ | งานรอดำเนินการ | ผู้ใช้รออนุมัติ · ลีดที่ยังไม่มีเจ้าของ · event ที่ส่ง Meta ไม่สำเร็จ |
| ผู้ใช้ | จัดการผู้ใช้ | เชิญ อนุมัติ เปลี่ยนระดับ มอบหมายโครงการ ปิดสิทธิ์ ย้ายลีด |
| โครงการ | จัดการโครงการ | เพิ่ม แก้ไข ปิดการขาย ตั้งมูลค่าต่อขั้น |
| รายงาน | ภาพรวมและ Export | หน้าเดียวกับของผู้บริหาร |
| ตั้งค่า | ตั้งค่าระบบ | Meta (Pixel ID, token, ทดสอบส่ง) · แคมเปญ · เหตุผลที่ไม่ซื้อ · ธีมและโลโก้ |

หมายเหตุ: ถ้าบริษัทเล็กและเจ้าของทำเองทุกอย่าง ให้ตั้งเจ้าของเป็นแอดมิน เพราะแอดมินเข้าหน้ารายงานของผู้บริหารได้อยู่แล้ว

## 3. ธีมและ CI

ทุกค่าด้านล่างเก็บเป็นตัวแปรใน global CSS ไฟล์เดียว ห้ามเขียนสีหรือขนาดฟอนต์ตรงๆ ในหน้าใดหน้าหนึ่ง ผู้เรียนเปลี่ยนสีแบรนด์ของบริษัทตัวเองได้โดยแก้ที่เดียว

### 3.1 ฟอนต์

- ฟอนต์: **IBM Plex Sans Thai** (น้ำหนัก 400, 500, 600)
- ขนาดฐาน: **16px** กำหนดที่ราก ขนาดอื่นทั้งหมดคิดเป็นสัดส่วนจากค่านี้ เปลี่ยนค่าเดียวแล้วเปลี่ยนทั้งระบบ

| ชื่อ | ขนาด | ใช้กับ |
|---|---|---|
| text-xs | 12px | ป้ายกำกับ เวลา |
| text-sm | 14px | ข้อความรอง |
| text-base | 16px | ข้อความทั่วไป ช่องกรอกทุกช่อง |
| text-lg | 18px | หัวข้อการ์ด |
| text-xl | 22px | หัวข้อหน้า |
| text-2xl | 28px | ตัวเลขสำคัญใน dashboard |

ช่องกรอกบนมือถือต้องไม่เล็กกว่า 16px เพื่อไม่ให้ iPhone ซูมหน้าจอเองตอนแตะช่อง

### 3.2 สี (ค่าเริ่มต้นของต้นแบบ)

| ตัวแปร | ค่า | ใช้กับ |
|---|---|---|
| --brand | #CF391A (แดงอมส้ม) | ปุ่มหลัก เมนูที่เลือกอยู่ |
| --brand-ink | #FFFFFF | ตัวหนังสือบนสีแบรนด์ |
| --ink | #1A1A1A | ตัวหนังสือหลัก |
| --ink-soft | #5F5F5F | ตัวหนังสือรอง |
| --surface | #FFFFFF | พื้นการ์ด |
| --bg | #F6F4F1 | พื้นหลังแอป |
| --line | #E3DFD9 | เส้นคั่น ขอบช่องกรอก |
| --ok | #1F6B45 (เขียวเข้ม) | สำเร็จ ขั้นที่ปิดการขายได้ |
| --warn | #E0A100 (เหลือง) | ต้องตามวันนี้ |
| --danger | #B3261E | เลยกำหนด ลบ |

แก้ 22 พ.ย. 2026: --brand เปลี่ยนจาก #E8431F เป็น #CF391A เพราะตัวหนังสือขาวบนสีเดิมได้ค่าความต่างสี 4.0 ต่อ 1 ต่ำกว่าเกณฑ์ 4.5 ของ WCAG 2.2 AA สีใหม่ได้ 4.94 บนพื้นขาว และ 4.5 บน --bg ผู้เรียนที่เปลี่ยนเป็นสีแบรนด์ของตัวเองต้องเช็กค่านี้ด้วย

มีโหมดมืดโดยสลับค่าตัวแปรชุดเดียวกัน ค่าสีโหมดมืดยังไม่ได้กำหนด

สถานะห้ามสื่อด้วยสีอย่างเดียว ต้องมีข้อความหรือไอคอนกำกับ เช่น "เลย 3 วัน"

### 3.3 ระยะและรูปทรง

- ระยะห่างใช้ชุดเดียว: 4, 8, 12, 16, 24, 32px
- มุมโค้ง: การ์ด 12px ปุ่มและช่องกรอก 8px
- ปุ่มและแถวที่กดได้สูงอย่างน้อย 44px
- จุดเปลี่ยนเลย์เอาต์: ต่ำกว่า 768px เป็นมือถือ (เมนูล่าง คอลัมน์เดียว) ตั้งแต่ 768px เป็นจอใหญ่ (เมนูซ้าย)
- ตารางบนมือถือแสดงเป็นการ์ดเรียงลงมา ไม่ให้เลื่อนซ้ายขวา

### 3.4 ชิ้นส่วนที่ใช้ซ้ำ

สร้างครั้งเดียวแล้วใช้ทุกหน้า: ปุ่ม · ช่องกรอก · การ์ดลูกค้า · ป้ายขั้น · แถบเมนู · หน้าต่างบันทึกกิจกรรม · สถานะว่าง ("ยังไม่มีงานวันนี้") · สถานะกำลังโหลด · ข้อความแจ้งผล

### 3.5 กติกาเพิ่ม (22 พ.ย. 2026)

อาจารย์อนุมัติหลังอ่านบทความ design trend 2027 ตัวอย่างอยู่ใน the mockup

1. **ความต่างสี** ตัวหนังสือขนาดปกติกับพื้นหลังต้องได้อย่างน้อย 4.5 ต่อ 1 (WCAG 2.2 AA)
2. **ปุ่มไอคอนต้องมีชื่อ** ปุ่มที่มีแต่ไอคอนต้องมี `aria-label` เป็นภาษาไทย ปุ่มที่ใช้บ่อยให้มีคำกำกับที่มองเห็นด้วย เช่น ปุ่มโทรเขียนว่า "โทร" เหตุผล: โปรแกรมอ่านหน้าจอและ AI ที่ใช้งานเว็บแทนคน (เช่น Claude in Chrome) อ่านปุ่มจากชื่อ ไม่ได้อ่านจากรูป
3. **การ์ดยืนยัน** การกระทำที่ผู้ทำย้อนเองไม่ได้ (เปลี่ยนแปลงเป็น "จอง" · ปิดสิทธิ์ผู้ใช้ · ย้ายลีดทั้งหมด) ต้องขึ้นการ์ดยืนยันที่แสดงรายละเอียดครบ (อะไร ของใคร มูลค่าเท่าไร และผลที่ตามมา) ปุ่มยืนยันบอกชื่อการกระทำ เช่น "ยืนยันจองแปลง A7" ไม่ใช้คำว่า "ตกลง"
4. **ปุ่มที่ยังกดไม่ได้** แสดงเป็นสีเทา เช่น ปุ่ม "อนุมัติ" ก่อนแอดมินเลือกระดับของผู้ใช้

## 4. แอปบนมือถือ (PWA)

- ติดตั้งจากเบราว์เซอร์ลงหน้าจอโฮมได้ มีไอคอนและชื่อแอป เปิดแล้วเต็มจอไม่มีแถบเบราว์เซอร์
- หน้า "ฉัน" มีปุ่มและคำอธิบายวิธีติดตั้ง แยก iPhone (ผ่าน Safari) และ Android (ผ่าน Chrome)
- โครงหน้าจอเปิดได้เร็วแม้สัญญาณอ่อน ข้อมูลล่าสุดที่เคยโหลดยังแสดงอยู่พร้อมบอกเวลาที่อัปเดต
- มีการแจ้งเตือนแบบ push (รายละเอียดในหัวข้อ 4.1)

### 4.1 การแจ้งเตือน (Push)

หลักการ

1. **ตัวเลขบนไอคอนแอป = จำนวนงานที่ยังต้องทำ** ไม่ใช่จำนวนข้อความที่ส่งมา ตัวเลขจึงลดเองเมื่อทำงานนั้นเสร็จ และเป็น 0 ได้เสมอ
2. **ข่าวที่แค่แจ้งให้ทราบไม่นับเป็นตัวเลข** เช่น "มีลูกค้าจองแล้ว" จะเด้งให้เห็นและเก็บไว้ในหน้า "แจ้งเตือน" ในแอป แต่ไม่เพิ่มตัวเลขบนไอคอน
3. **รวมเป็นข้อความเดียว** งานตาม 5 รายส่งเป็น 1 ข้อความ ไม่ส่ง 5 ข้อความ
4. **ทุกข้อความขึ้นต้นด้วยชื่อโครงการ** และกดแล้วเปิดไปที่หน้าของเรื่องนั้นโดยตรง

เซลส์

| เมื่อไร | ข้อความตัวอย่าง | กดแล้วไปที่ |
|---|---|---|
| ทุกเช้า (เวลาตั้งได้) | วันนี้ต้องตาม 5 ราย · เลยกำหนด 2 ราย | หน้า "วันนี้" |
| มีลีดใหม่ถูกมอบหมาย (ทันที) | [โครงการ A] ลีดใหม่: คุณสมชาย | หน้าลูกค้ารายนั้น |
| ก่อนเวลานัดชม 1 ชั่วโมง | [โครงการ A] นัดชม 14:00 คุณสมชาย | หน้าลูกค้ารายนั้น |

ตัวเลขบนไอคอนของเซลส์ = งานเลยกำหนด + งานวันนี้ที่ยังไม่ได้บันทึกผล + ลีดใหม่ที่ยังไม่ได้ติดต่อ

ผู้บริหาร

| เมื่อไร | ข้อความตัวอย่าง | กดแล้วไปที่ |
|---|---|---|
| ทุกเย็น (เวลาตั้งได้) | สรุปวันนี้: ลีดใหม่ 12 · นัดชม 3 · จอง 1 · งานเลยกำหนดทั้งทีม 7 | หน้า "ภาพรวม" |
| มีการจอง ทำสัญญา หรือโอน (ทันที) | [โครงการ A] จองแล้ว 1 ราย โดยเซลส์ สมหญิง | หน้าลูกค้ารายนั้น |

- ตัวเลขบนไอคอนของผู้บริหาร = จำนวนงานตามที่เลยกำหนดของทั้งทีม (เฉพาะโครงการที่เลือกรับแจ้งเตือน) ตัวเลขนี้ลดเมื่อเซลส์ตามงานเสร็จ ไม่ได้ลดจากการเปิดอ่าน กดแล้วไปที่รายการงานเลยกำหนดแยกรายเซลส์
- ข่าวที่แค่แจ้งให้ทราบ (จอง ทำสัญญา โอน) ไม่นับเป็นตัวเลข แสดงเป็นจุดบนปุ่ม "แจ้งเตือน" ในแอป และหายเมื่อเปิดหน้านั้น
- หลายโครงการ: บรรทัดแรกของสรุปเป็นยอดรวมทุกโครงการ เปิดเข้ามาในหน้า "ภาพรวม" จะเห็นตัวเลขแยกรายโครงการเรียงลงมา และกรองดูทีละโครงการได้
- ผู้บริหารเลือกได้ว่าจะรับแจ้งเตือนของโครงการไหนบ้าง

แอดมิน

| เมื่อไร | ข้อความตัวอย่าง | กดแล้วไปที่ |
|---|---|---|
| มีผู้ใช้สมัครรออนุมัติ (ทันที) | มีผู้ใช้ใหม่รออนุมัติ 1 ราย | หน้า "งานรอ" |
| ส่ง event ไป Meta ไม่สำเร็จ (สรุปวันละครั้ง) | ส่งข้อมูลไป Meta ไม่สำเร็จ 3 รายการ | หน้า "งานรอ" |

ตัวเลขบนไอคอนของแอดมิน = จำนวนงานรอดำเนินการ

การตั้งค่าของผู้ใช้แต่ละคน (หน้า "ฉัน")

- เปิดปิดการแจ้งเตือนแต่ละประเภท
- เวลาส่งสรุปประจำวัน
- ช่วงเวลาห้ามรบกวน

ข้อจำกัด

- iPhone: ต้องติดตั้งแอปลงหน้าจอโฮมก่อน แล้วกดอนุญาตการแจ้งเตือนจากในแอป ถึงจะรับ push ได้
- Android: บางรุ่นแสดงเป็นจุดบนไอคอนแทนตัวเลข
- ไม่มีค่าใช้จ่าย ใช้มาตรฐาน Web Push ของเบราว์เซอร์ และให้ cron-job.org เรียกระบบตามเวลาเพื่อส่งสรุปประจำวัน

## 5. กติกาทางเทคนิค

### 5.1 การโหลดข้อมูล

- หน้าที่มีตัวกรองหลายตัว หรือต้องรวมตัวเลข ให้เรียกผ่าน **RPC (ฟังก์ชันในฐานข้อมูล) ของ Supabase** ครั้งเดียวต่อหน้า ไม่ดึงข้อมูลดิบมาคำนวณในเครื่องผู้ใช้
- RPC ที่ต้องมี: งานของฉันวันนี้ · รายการลูกค้าพร้อมตัวกรอง · ตัวเลข dashboard · funnel รายโครงการ · สรุปรายเซลส์ · ข้อมูลสำหรับ Export
- รายการยาวโหลดทีละ 30 แถว เลื่อนถึงท้ายแล้วโหลดต่อ
- ใส่ index ที่คอลัมน์ที่ใช้กรองบ่อย: โครงการ, เซลส์, ขั้น, วันตามครั้งถัดไป
- RPC ทุกตัวต้องเช็กสิทธิ์ของผู้เรียกตามระดับผู้ใช้

### 5.2 รูปภาพ

- ย่อรูปในเครื่องผู้ใช้ก่อนอัปโหลดทุกครั้ง: ด้านยาวไม่เกิน 1600px บีบอัดให้ไฟล์ไม่เกินประมาณ 300KB
- เก็บรูปใน Supabase Storage แบบส่วนตัว เปิดดูได้เฉพาะผู้มีสิทธิ์

### 5.3 การบันทึกแบบไม่ต้องรอ

- ข้อความบันทึกทันที แล้วปิดหน้าต่างเลย
- รูปอัปโหลดเบื้องหลัง ผู้ใช้ทำงานต่อได้ทันที มีป้าย "กำลังอัปโหลดรูป" บนกิจกรรมนั้น และลองใหม่เองถ้าไม่สำเร็จ
- ข้อจำกัด: เว็บแอปบนมือถือ โดยเฉพาะ iPhone อัปโหลดต่อไม่ได้เมื่อปิดแอปหรือล็อกจอ ระบบจึงเก็บคิวไว้ในเครื่อง และอัปโหลดต่อเมื่อเปิดแอปอีกครั้ง
- การส่ง event ไป Meta ทำเบื้องหลังเช่นกัน ไม่ให้เซลส์รอ ถ้าส่งไม่สำเร็จจะเข้าคิวให้งานประจำวันส่งซ้ำ

### 5.4 ความปลอดภัย

- เปิด Row Level Security ทุกตาราง
- token ของ Meta เก็บฝั่งเซิร์ฟเวอร์เท่านั้น ไม่ส่งมาที่เครื่องผู้ใช้
- ลิงก์เชิญใช้ได้ครั้งเดียวและมีวันหมดอายุ

## 6. สิ่งที่ยังต้องตัดสินใจ

1. ชื่อแอปและไอคอนของต้นแบบ
2. ค่าสีโหมดมืด

4. ต้องมีระดับ "หัวหน้าทีม" คั่นระหว่างผู้บริหารกับเซลส์หรือไม่ (ตอนนี้ตัดออกเพื่อให้ง่าย)
